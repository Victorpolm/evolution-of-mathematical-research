The architecture is viable for a pilot: tens-of-MB releases, precomputed aggregates, and GitHub Pages are proportionate. It is not public-launch ready because per-paper publication contradicts the project’s own ethics boundary, the trusted-runner isolation is underspecified, and operations have an institutional bus factor of one. Legal points below are risk judgments, not jurisdiction-specific advice.

1. **[legal] Per-paper labels break the stated safety boundary.** [§1 publishes classification and human-review labels by arXiv ID](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:10), contradicting the pitch’s “aggregate reporting only; no per-paper accusations” rule. **Failure:** one false “result-bearing AI” or detector label becomes a searchable, reputationally damaging assertion copied beyond correction. **Mitigation:** expose per-paper rows only for human-verified, explicit author disclosures—worded as “the document contains a disclosure”—and keep detector, non-disclosure, and reliability findings aggregate-only, with an appeal/correction process.

2. **[pr-model] A reviewed PR is still hostile code on the trusted box.** [§2 sends “new extractors” from PR approval to the corpus-holding runner](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:28). **Assumption:** contributor extractor code is executed there. **Failure:** a plausible extractor exfiltrates corpus material or credentials, corrupts the database, or launches an expensive job; pinning the pipeline does not sandbox new code. **Mitigation:** run only a protected merged commit in an ephemeral VM/container with read-only corpus, no network or secrets, strict resource/output allowlists, and two-person Tier-0 approval.

3. **[legal] arXiv IDs do not anonymize authors.** The assertion that “IDs + derived labels” are legally publishable [in §1](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:13) ignores that IDs trivially resolve to named authors. **Assumption:** the controller is the Swiss/ETH project; a paper-level reputational label may count as information relating to identifiable people. Swiss FDPIC research guidance favors non-identifiable publication when relying on research provisions, while GDPR—if applicable—provides access, rectification, and objection rights ([FDPIC](https://www.edoeb.admin.ch/en/research-and-data-protection), [GDPR Articles 4, 14, 16 and 21](https://eur-lex.europa.eu/eli/reg/2016/679/oj)). **Mitigation:** obtain ETH privacy/legal review, document the legal basis and risk screening, publish a privacy notice and rights contact, and support prompt correction/objection.

4. **[sustainability] Trusted compute is personally, not institutionally, anchored.** [§3 places the corpus on “a D-MATH member’s” user partition and makes one AWS account the fallback](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:42). **Failure:** departure, illness, account suspension, or policy change stops Tier-0 releases and even urgent label corrections. **Mitigation:** establish institution-owned storage and service identities, at least two authorized maintainers, a tested cold-start recovery path, and an explicit operating agreement before launch.

5. **[pr-model] Tier-0 is auditable, not presently reproducible.** [§2 says anyone with bulk access can re-derive](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:30), but recording only pipeline/model versions and scan IDs does not freeze proprietary LLM/Pangram behavior, decoding parameters, prompts, or human adjudication. **Failure:** an independent runner cannot reproduce disputed labels months later. **Mitigation:** release an input manifest and hashes, container digest, code commit, prompts, parameters, output commitments, and adjudication log; describe the guarantee as “auditable repeatability” unless a second trusted institution reproduces each major release.

6. **[data-release] The canonical data home cannot remain an open choice.** [§5 offers Releases or a sibling data repo, with Zenodo only “later”](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:92). **Failure:** repeated Parquet snapshots bloat a Git repository, while website, GitHub asset, and paper DOI silently identify different bytes. GitHub Releases readily fit this scale—2 GiB per asset—but GitHub recommends generated data outside Git; Zenodo supplies version-specific and concept DOIs ([GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases), [Zenodo](https://zenodo.org/help/versioning)). **Mitigation:** make Zenodo the canonical versioned dataset from v1, mirror identical checksummed assets in GitHub Releases, and optionally use Hugging Face only as a Parquet viewer/query mirror.

7. **[data-release] Checksums do not define correction semantics.** [§1 promises versioned releases](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:15) but does not say what happens when a person disputes a released row. **Failure:** silently replacing an asset destroys reproducibility; leaving a false DOI snapshot unqualified prolongs harm, and Zenodo deletion after 30 days generally requires a justified support request ([Zenodo policy](https://help.zenodo.org/docs/deposit/manage-records/)). **Mitigation:** never overwrite releases; publish a new version plus a machine-readable correction/withdrawal ledger, make every old landing page surface supersession notices, and document an emergency takedown route.

8. **[legal] Metadata licensing is sound; the blanket conclusion is not.** Established fact: arXiv descriptive metadata—including authors, identifiers, abstracts, and classifications—is CC0 and may be transformed and shared ([arXiv API terms](https://info.arxiv.org/help/api/tou.html)). That CC0 grant does not automatically license the project’s new annotations, while most article content remains non-redistributable under the default article license ([arXiv licensing](https://info.arxiv.org/help/license/index.html)). **Failure:** downstream users treat annotations as arXiv-endorsed CC0 metadata, or evidence snippets creep into releases. **Mitigation:** give project-created fields an explicit dataset license and provenance namespace, exclude expressive source excerpts, link back to arXiv, and state non-endorsement.

9. **[pr-model] Tier-1 needs a data-only security boundary.** [§2 permits community queries/specs and §5 runs them in Actions](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:23). **Assumption:** PRs are not structurally restricted to a declarative directory. **Failure:** a contributor alters build dependencies/workflows, submits resource-exhausting SQL, or embeds external tracking URLs in a chart. **Mitigation:** accept only schema-validated query/spec files; enforce local data URLs, SQL/time/memory/result limits, CODEOWNERS, and a base-branch `pull_request` workflow on disposable GitHub-hosted runners with read-only tokens and no secrets—never privileged `pull_request_target`, as [GitHub warns](https://docs.github.com/en/actions/reference/security/secure-use).

10. **[site] A rendered chart is not a sufficient scientific review unit.** [§2 says review sees the rendered chart, while §4 calls each spec the PR-able analysis unit](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:63). **Failure:** an attractive chart with a wrong denominator, selective interval, or invalid uncertainty calculation enters the authoritative dashboard, making the maintainer an overloaded journal editor. **Mitigation:** separate a tightly curated “core findings” dashboard from a visibly labeled community gallery; require a pinned release hash, estimand, query, expected-result tests, limitations, and statistical/domain review for core promotion.

11. **[site] DuckDB-WASM is realistic only as an opt-in enhancement.** [§4 proposes querying the full annotation Parquet in-browser](/mnt/z/ArxivObservatory/DESIGN_PLATFORM.md:65). **Failure:** repeated tens-of-MB loads perform poorly on constrained phones, approach Pages’ 100-GB/month soft bandwidth limit, or fail when cross-origin asset hosting lacks CORS/range support; DuckDB-WASM is single-threaded by default and browser-memory constrained ([DuckDB](https://duckdb.org/docs/stable/clients/wasm/overview), [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)). **Mitigation:** keep all primary views on small precomputed aggregates, lazy-load a sharded Parquet explorer behind an explicit action, host shards on a CORS/range-capable data endpoint, and provide a non-WASM fallback.

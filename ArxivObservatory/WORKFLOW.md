# Operator runbook — v2 pipeline (2026-08-10)

Current workflow for the immutable-evidence pipeline. The legacy
`arxiv_ai_ack_scan.py` path is deprecated (pilot history only; do not run).

## Run discipline (applies to every stage)

- Run ids are immutable and never reused; rescans/reclassifications create
  NEW runs (`--supersedes <old>` marks the old one superseded — metadata
  only, evidence is never deleted).
- Every scan writes one `scan_items` row per paper (ok / error / skipped):
  "scanned" is a provable property, absence of hits is not.
- Reports and the site are pure functions of ONE scan run + ONE
  classification run; `--freeze <release-id>` records the release manifest.
- Schema changes only via `python3 -m pipeline.migrate --apply` (additive
  migrations; automatic backup to `backups/` first).
- Never change lexicon/taxonomy and gold labels in the same commit (E1).
  Bump `LEXICON_VERSION` / `TAXONOMY_VERSION` on any change.

## Stages

```bash
# 0. schema (once per code update)
python3 -m pipeline.migrate --apply

# 1. metadata harvest (OAI-PMH, polite; incremental)
python3 -m pipeline.harvest --from 2026-08-01 --until 2026-08-31
# historical backfills: pipeline/backfill.sh (chunked)

# 2. metadata keyword scan (whole-frame first signal)
python3 -m pipeline.scan_meta --primary-math [--from ... --until ...]

# 3a. targeted full-text fetch (export.arxiv.org, version-pinned, 4s spacing)
python3 -m pipeline.fetch --months 2608 2607
# 3b. bulk corpus (3-year segment): EC2 filter (pipeline/aws/README.md), then
rsync ... corpus/s3/                       # sync_home.sh
python3 -m pipeline.aws.import_s3          # reconcile (two-direction + sha256)
python3 -m pipeline.aws.import_s3 --register   # gate passed -> register

# 4. full-text scan (immutable run; id autogenerated, e.g. tex-20260810T154813)
python3 -m pipeline.scan --corpus [--months 2308 ...] [--supersedes <old-run>]

# 4b. v1-estimand path (bulk blobs are re-rolled "latest", NOT v1): refetch
#     pinned v1 for multi-version papers, then scan version-pinned artifacts.
#     Refill outcomes ledger: corpus/logs/v1refill_attempts.jsonl.
#     Every invocation is EXACTLY one authorized mode (review-6):
ARXIV_FETCH_DELAY=6 python3 -m pipeline.fetch --v1-refill \
    --flagged-only --flagged-first <scan-run> --months <all yymm>
#     ... or, ONLY after arXiv coordination (DECISIONS.md):
#     ... --include-unflagged-tail --months <all yymm>
python3 -m pipeline.scan --v1-corpus [--flagged <scan-run>]   # run id texv1-*
#     (--v1-corpus = explicit version=1 artifacts + single-version papers'
#     bulk blobs, which are metadata-certain v1; consumes artifacts, not files)

# 5. LLM classification (pin the model for analysis runs; isolate = one
#    paper per call, prompt-injection containment). Preferred for analysis:
#    the direct non-agentic API backend (implies isolation; tokens metered;
#    keys in gitignored .env; ALWAYS set the owner USD cap — it reserves
#    per physical dispatch and persists spend across resumes)
python3 -m pipeline.classify --backend api --runs <scan-run> \
    --model gpt-5.6-luna --max-usd-per-provider 50 \
    --budget-approval DECISIONS-2026-08-11   # cap+approval MANDATORY
python3 -m pipeline.classify --runs <scan-run> --model <model-id> --isolate
python3 -m pipeline.classify --resume <cls-run> --runs <scan-run> ...  # continue
#    Campaign lifecycle (review-10 B5): create-campaign (owner step) ->
#    classify runs against it -> amend-campaign (append-only events) ->
#    close-campaign after provider-console reconciliation. call_api REFUSES
#    to spend without an attached campaign. Scoped runs
#    (--papers-file) are identity-bound (protocol hash) and terminal as
#    complete_scoped — report/freeze refuse them (adherence/dev only).
#    The approval id names a durable budget CAMPAIGN (budget_campaigns):
#    spend is scoped to that id across processes/resumes; one approval =
#    one provider+model+cap. A new approval id starts a fresh campaign that
#    inherits NOTHING from prior pilots (review-8 B1).
#
#    Analysis-run COMPLETION CRITERION (review-8 B5; invariants corrected
#    per review-9 B6 — the cardinality is NOT 1:1) — before any freeze:
#    * every classifiable snippet in exactly ONE terminal state (ok /
#      invalid / reason-coded error); zero unresolved length/ID/schema
#      errors; single-snippet terminal failures inspected and bounded in
#      the report, never omitted;
#    * relational invariants: every physical dispatch has exactly one
#      pre-dispatch api_spend reservation AND one api_attempts row (updated
#      with its response); every logical request maps an ordered snippet
#      set to >=1 attempts; every stored label maps back to the request/
#      attempt/protocol that produced it; every reservation ends settled,
#      released-with-reason, or as a NAMED reconciliation exception;
#    * campaign totals reconcile to provider-console billing within a
#      declared tolerance, acknowledged by the owner in DECISIONS.md.

# 6. render-truth check (evidence must occur in the arXiv-compiled PDF;
#    fuzzy matches get render_status 'rendered_fuzzy' = review-queue, and the
#    --require-rendered gate does NOT count them)
python3 -m pipeline.render_check --run <cls-run>

# 7. report + frozen release
python3 -m pipeline.report --scan-run <scan-run> --classification-run <cls-run> \
    --from 2026-07-01 --until 2026-08-08 \
    --require-grounded --require-rendered --freeze <release-id>

# 8. site (same scoping as the report)
python3 -m pipeline.build_site --scan-run <scan-run> \
    --classification-run <cls-run> --require-grounded --require-rendered

# 9. gold study (GOLD_STUDY.md) — sample, blinded packets, ingest, agreement.
#    A release-bound sample MUST scope to the report cohort (review-5 P0-9):
python3 -m pipeline.annotate build --project gold-v1 --scan-run <scan-run> \
    --classification-run <cls-run> --from <d0> --until <d1> \
    --category-like 'math%' --require-grounded --require-rendered \
    --reviewers <r1> <r2> --out annotation/gold-v1
python3 -m pipeline.annotate ingest --project gold-v1 --json <export> --reviewer <r1>
python3 -m pipeline.annotate agreement --project gold-v1
```

## Data boundaries

- `corpus/`, `papers/`, `observatory.db`, `backups/`, `annotation/` are never
  committed (arXiv license, privacy, aggregate-only policy).
- Public outputs are aggregates from a frozen release; per-paper excerpts
  stay in restricted, gitignored locations (LB-07).
- Legacy tables (`files`, v1 scan runs `tex-v1`/`meta-v1`,
  `classifications`, `human_review`) are frozen forensic history; new stages
  write only to the v2 run/item/evidence tables.

## Ops notes

- WSL/DrvFs: archives are scanned in memory, never extracted (small-file I/O);
  the bulk corpus is read directly from monthly tars via `tar::member` paths.
- Long remote jobs: tmux, not nohup (pipeline/aws/README.md).
- Analysis classification uses the direct API backend (DECISIONS.md);
  the codex CLI remains available for development only. Prefer bulk
  batches for subscription economics; use `--isolate` for analysis runs.
- AI cross-checks (CROSSCHECK.md) find kinks; the blinded human gold study
  (GOLD_STUDY.md) is the only validity bar.
